# Design review

Use the same browser, zoom level and viewport when comparing versions. Start at 100% zoom, then inspect a narrow window and 200% zoom. Compare the standalone pages for desktop layout; two side-by-side panes each have less horizontal space and may switch to a responsive layout.

## Five-minute task per design

1. Find a remote Java opportunity.
2. Open its details and check salary, location and office days.
3. Save it, open Saved, then remove it.
4. Open Profile and choose Use example.
5. Change work mode to Hybrid, choose two days, then save.
6. Change the city. Confirm the summary still shows the last save.
7. Navigate with Tab and open/close details using the keyboard.
8. Narrow the browser. Check the form, filters and reading order.

The Current profile includes the existing hero; use the Profile link or scroll to compare the form itself. The catalog in Current is a future extension, not an existing product feature.

## Record observations

| Area | Question |
| --- | --- |
| Overall direction | Which version feels most like JobSinton? |
| Hierarchy | Where does attention go first? Is that useful? |
| Density | Can two offers be compared without excessive scrolling? |
| Palette | Does the green remain distinctive without dominating? |
| Typography | Are titles distinctive and details easy to read? |
| Navigation | Is the next action obvious? |
| Forms | Are labels, errors and the last-saved summary clear? |
| Shapes | Do borders and corners feel restrained and consistent? |
| Mobile | Is the reading order comfortable and are controls easy to activate? |

Use the parent page's **Keep the best parts** form to download notes. The form does not retain notes after closing the page.

Useful feedback is specific: “Folio titles, Current green, Ledger filter rail, Atlas form spacing.” A whole version does not need to win.

## Suggested starting point

Start with Current and Folio. Then compare Ledger for density and Atlas for navigation. Review Nocturne as an optional dark direction. This is a review order, not a claim that one design has tested better.

## After selection

Record the selected palette, type scale, layout, component states and responsive behavior in `docs/DESIGN.md`. Implement the selected system in a focused increment before adding the fictional catalog. Keep the existing profile behavior and verification contract intact.
